## 1. Goal and ground truth

Build a static, uncluttered, brand-themed webpage that showcases the Sanjivani Vikas Foundation asset pack, with a download link on every asset. Publish it on GitHub Pages. All assets are committed to the same repo.

**Ground truth files (the only sources of fact):**

| File | What it is |
|---|---|
| `asset-inventory.json` | Measured facts for all 42 asset files: size, dimensions, colour mode, real transparency, sha256, known flags, and the mechanical destination path. |
| `source/README_Sanjivani_Asset_Pack.md` | Owner's README: brand colours, tagline, production notes. |
| `Elements.zip` | The original files. Never modified. |

Brand facts (from the README, copy exactly, never eyedrop or guess):

- Sanjivani Orange `#FF6A00`, Sanjivani Green `#0D6B3A`, Support Cream `#FFF5E6`
- Tagline: `PEOPLE | PARTNERSHIP | PROGRESS`
- The supplied official logo is the source of truth. Never redraw, recolour, crop or distort it.

**Stack: plain static HTML, CSS and vanilla JS. No framework, no build step for the site, no npm dependencies, no CDN.** Fewer moving parts means fewer places to hallucinate. Python 3 with Pillow is allowed for helper scripts only.

## 2. Anti-hallucination rules

1. **Files:** use only files listed in `asset-inventory.json`. Never reference, create or "find" an image, icon, font or logo that is not in it. No stock images, no AI-generated placeholders, no external image URLs.
2. **Numbers:** every dimension, file size and format shown on the page must be generated from `data/manifest.json`, which is generated by a script reading the real files. Never type a dimension or size by hand.
3. **Text:** the only allowed copy is (a) text from the README, (b) labels derived mechanically from filenames, (c) neutral UI labels such as "Download", "PNG", "Copy hex". Do not write marketing text, an "About us" story, founding year, address, contact details, statistics, testimonials or claims about what the Foundation does. If a section needs copy you do not have, write `TODO(owner)` in `CONTENT_NEEDED.md` and leave that section out of the page.
4. **Images:** do not describe what is inside an image unless you have actually viewed it. If you have not viewed it, alt text = the label only.
5. **Never modify original bytes.** Originals are copied and renamed only. After copying, verify every sha256 against `asset-inventory.json`.
6. **Do not "fix" the owner's files or names.** Do not correct typos (for example "Goood Job") or resize, recompress or crop originals. Flag and ask.
7. **Ask, do not guess.** If anything is ambiguous, stop, list the question in `QUESTIONS.md`, and wait. Do not choose a default silently.
8. **Do not claim anything works without evidence.** After each phase, run the verification command and paste its real output. "Should work" is not acceptable.
9. **Versions and commands:** do not guess package versions, GitHub Actions versions, or Pages settings from memory. If you need one, look it up in the official documentation and state the source. Prefer approaches that need none.
10. **One phase at a time.** Complete the gate, commit, report, then continue. Do not start the next phase early. Do not touch files outside the current phase.
11. **Scope:** do not add features, pages, animations, analytics, trackers, cookie banners or dependencies that are not in section 5.
12. **Relative paths only** (no leading `/`), because project sites are served from `/<repo-name>/`.

If you catch yourself about to break a rule, stop and write the conflict in `QUESTIONS.md`.

## 3. Repo layout and naming

```
<repo>/
├── index.html
├── .nojekyll
├── README.md
├── MASTER_PLAN.md
├── asset-inventory.json
├── QUESTIONS.md              (created only if needed)
├── CONTENT_NEEDED.md         (created only if needed)
├── css/style.css
├── js/app.js
├── data/manifest.json        (generated, never hand-edited)
├── source/README_Sanjivani_Asset_Pack.md
├── assets/
│   ├── original/<category>/  (renamed copies of the originals, bytes untouched)
│   └── web/<category>/       (generated .webp previews, max 1200 px wide)
└── scripts/
    ├── copy_originals.py
    ├── make_previews.py
    ├── build_manifest.py
    └── verify.py
```

**Categories (fixed):** `01-brand`, `02-mascot`, `03-icons`, `04-stickers`, `05-banners`, `06-web-ui`, `07-vector`.

**Naming rule (mechanical only):** lowercase, every run of non-alphanumeric characters becomes one hyphen, keep the extension. Example: `Sanjivani Get Started Button_1.png` becomes `sanjivani-get-started-button-1.png`. The exact destination of every file is already in `asset-inventory.json` under `dest_path`. Use that, do not invent your own.

Reason: GitHub Pages is case-sensitive and spaces in URLs break links.

## 4. Known issues in the assets (display honestly)

These were measured, not assumed. The page must not hide or contradict them.

| Issue | Required handling |
|---|---|
| `Sanjivani_original_colours.svg` is **not a true vector**. It is one embedded base64 PNG inside an SVG wrapper (5.4 MB). | Do not label it "scalable" or "editable vector". Label it "SVG (embedded raster)". Show its real size. |
| `Sanjivani Outline.svg` is a true vector (297 paths, black fill, 400x600pt). | Label as "SVG, single-colour outline". |
| `App Icon_1024.png` is actually **1254x1254**, RGB, no transparency. | Show 1254 x 1254, taken from the manifest. Never print "1024". |
| `Cheerful Sunflower Mascot Badge.png` is 1254x1254, opaque, and not in the README. | Show as measured. Ask the owner what it is (QUESTIONS.md). |
| README lists a "Circular DP 1024" but no file clearly matches. | Do not show a "Circular DP" item. Ask the owner. |
| Sticker PNGs are 1206 to 1774 px wide. WhatsApp sticker packs need their own format. | Call them "sticker artwork (PNG)". Never write "WhatsApp-ready". |
| `T 3 by 4 Flower Mascot Guide.png` is 1086x1448, unlike the other views (1024x1536). | Ask the owner whether it is a guide sheet or the 3/4 view before labelling it. |
| `Sanjivani Good Job.png` and `Sanjivani Goood Job.png` both exist. | Show both, unrenamed. Ask the owner which is final. |
| README says "PMJJY" once and "PMJJBY" elsewhere. | Use the exact filename. Add to QUESTIONS.md: proofread campaign text inside the stickers. |
| Social banners are opaque RGB. All other PNG files with alpha have real transparent pixels. | Show transparent assets over a checkerboard toggle, so transparency is visible. |

## 5. Page specification

One page, `index.html`, anchor navigation. Brand colours via CSS variables. Light cream background (`#FFF5E6`), green for text and buttons, orange for accents. System font stack (no web fonts). Uncluttered, generous spacing, mobile first.

**Sections, in order (all rendered from `data/manifest.json` by `js/app.js`, with a static fallback `<noscript>` message):**

1. **Header and hero:** official emblem, wordmark, tagline. Nothing else.
2. **Brand identity:** emblem, wordmark, tagline files; three colour cards with the README hex values and a "Copy hex" button.
3. **Mascot:** the character view files as a grid.
4. **Icons:** six icon files, each labelled with its real pixel size.
5. **Stickers:** sticker grid.
6. **Social banners:** two banners at full width, real sizes shown.
7. **Web and UI elements:** seven items on a checkerboard/cream background toggle.
8. **Vector:** the two SVG files with the honest labels from section 4.
9. **Usage notes:** the README "Important production notes" rewritten as a short list, wording faithful to the README.
10. **Footer:** foundation name and the tagline. Nothing invented.

**Every asset card:** preview (`.webp`, `loading="lazy"`, explicit `width` and `height`), label, format, pixel size, file size, and a **Download** link pointing to the file in `assets/original/` using the `download` attribute.

**Not allowed:** animations on scroll or cursor, carousels, popups, counters, fake numbers, testimonials, emoji as icons, external fonts or scripts, "made with AI" badges.

**Must have:** favicon (use `sanjivani_favicon_64.png`), correct `<title>`, `lang`, meta description built only from README wording, keyboard-accessible controls, alt text on every image, visible focus states.

## 6. Phases and verification gates

Report after each phase with the real command output. Commit after each gate passes.

### Phase 0: Read and confirm
- Read this file, `asset-inventory.json` and the README.
- Create `QUESTIONS.md` from section 4 (only the "ask the owner" items).
- **Gate:** reply with a 10-line summary of what you will build and which items you need answered. **Stop and wait for the owner's go-ahead.**

### Phase 1: Repo scaffold and originals
- Create the layout from section 3.
- `scripts/copy_originals.py` copies each source file to its `dest_path`.
- **Gate:** `python scripts/verify.py --originals` prints `42/42 sha256 match` and `0 files with spaces or uppercase in name`.

### Phase 2: Previews and manifest
- `scripts/make_previews.py`: `.webp` previews, max 1200 px wide, quality about 82, preserving alpha. SVGs are not converted. Originals are never touched.
- `scripts/build_manifest.py`: writes `data/manifest.json` from the files on disk (path, preview path, category, bytes, width, height, format, transparency).
- **Gate:** `verify.py --manifest` prints that every manifest path exists and every file in `assets/original/` appears in the manifest. Report total size of `assets/web/`.

### Phase 3: Page
- Build `index.html`, `css/style.css`, `js/app.js` per section 5.
- **Gate:** run a local server (`python -m http.server`), then `verify.py --links` which checks every `href` and `src` resolves to a real file, with no absolute paths and no external URLs. Open the page at 360 px and 1280 px widths and confirm no horizontal scroll. Show screenshots if you can.

### Phase 4: Content check
- Compare every piece of visible text against the allowed sources in rule 3.
- **Gate:** produce a table of all text strings on the page with its source (README line, filename, or UI label). Any string without a source is removed.

### Phase 5: Publish
- Follow section 7.
- **Gate:** the live URL loads, five randomly chosen Download links return HTTP 200 from the live site, and the downloaded file's sha256 matches `asset-inventory.json`.

## 7. GitHub Pages deployment

Use the simplest method: **deploy from branch** (`main`, folder `/ (root)`), with an empty `.nojekyll` file in the root. No GitHub Actions workflow is needed for this site.

- Do not guess the Settings menu wording. Check the current GitHub Pages documentation and cite it.
- Large files: the largest asset is about 5.4 MB, so no Git LFS is needed. Total originals are about 66 MB, which is acceptable for a normal repo. Do not commit the zip itself.
- All links must stay relative so the site works at `https://<user>.github.io/<repo>/`.
- Optional, only if the owner asks later: per-category ZIP download. Do not add this unless asked.
